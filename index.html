Prompt Engineering & Viva Documentation

Prepared prior to generating code to satisfy Section 2.2 of the Prompt Engineering Final Project Guidelines:

1. Role

"Act as a Senior Full-Stack Web Developer and Product Designer specializing in high-utility consumer productivity apps for college students and Gen-Z creators."

2. Task

"Create 'HypeSmart AI', a responsive web application combining three interactive student tools—(1) Viral Hook & Script Lab, (2) SubTracker & Student DealFinder, and (3) Weighted Smart Decision Matrix—integrated with a persistent live Gemini AI Copilot."

3. Context

"College students and young adults struggle with short-form content ideation, wasted money on forgotten subscriptions, and decision paralysis over tech purchases or career choices. This hub solves all three in one cohesive workflow."

4. Constraints

"Use semantic HTML5, Tailwind CSS via CDN, and vanilla ES6 JavaScript in a single self-contained file with a dark-mode aesthetic (#0B0F19). Connect the chatbot to the live Gemini API with input validation, retry logic, error handling, and zero hardcoded API keys."

5. Output Format

"Deliver a complete, runnable index.html file with a top module switcher, interactive forms and visual progress bars, a persistent side-panel AI Copilot, and a tabbed Prompt & Viva Docs modal."

Documented prompt iterations demonstrating how structured refinement improved application accuracy and UX (Section 2.4):

v1 → v2: Dynamic Tab-Aware Context Injection Context Prompting

Before (v1): Generic chatbot system prompt had no awareness of which module the user was currently editing.

After (v2): Updated systemInstruction dynamically on every send to inject the active tab name plus live state (generated script, subscription list, or decision matrix scores).

v2 → v3: Persona Guardrails & Concise Formatting Constraint + Role Prompting

Before (v2): AI responses were verbose 400-word paragraphs that overflowed the side-panel chat window.

After (v3): Constrained the AI persona to reply in under 140 words using crisp bullet points, INR (₹) currency formatting, and actionable next steps.

v3 → v4: Resilient Error & Security Handling Edge-Case Prompting

Before (v3): Blank prompts or missing API keys failed silently without user feedback.

After (v4): Added client-side length validation, exponential backoff retries, inline error alerts, and a localStorage key drawer so zero secrets are committed to GitHub.

Rule Compliance (Section 2.6): Never push API keys to a public GitHub repository. To deploy safely on Vercel, add an api/chat.js serverless proxy and store GEMINI_API_KEY in Vercel's Environment Variables: 

// api/chat.js (Vercel Serverless Function — keeps API key 100% hidden)
export default async function handler(req, res) {
  if (req.method !== 'POST') return res.status(405).json({ error: 'Method not allowed' });
  const { contents, systemInstruction } = req.body;
  const response = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/gemini-3-flash-preview:generateContent?key=${process.env.GEMINI_API_KEY}`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ contents, systemInstruction })
    }
  );
  const data = await response.json();
  return res.status(response.status).json(data);
}
